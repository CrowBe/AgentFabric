# Upstream OAuth for remote MCP sources

The operator connects a remote MCP server that needs OAuth 2.0 / 2.1 sign-in. The source starts as `auth required`. The operator or a harness gets a gateway URL, signs in once at the provider, and the gateway finishes the PKCE code exchange, stores the tokens in its vault, and refreshes them automatically. Harnesses never see upstream tokens. Other sources and imported bundles cannot reference the vault names the gateway manages for OAuth, and exports stay secret-free.

## Sub-features

- `oauth-recipe` creates an `mcp_http` source with `authConfig.kind: oauth2` from the `mcp-http-oauth` starter recipe or a custom source, with health `auth_required`.
- `oauth-status` reports `configured`, `connected`, `redirectUri`, `hasRefreshToken`, and the endpoints over `GET /api/sources/<id>/oauth`, with no token values.
- `oauth-start` returns a single-use `authorizeUrl` (PKCE `S256`, `state=af_oauth_state_…`, `redirect_uri=<gateway>/auth/oauth/callback`) from `POST /api/sources/<id>/oauth/start`.
- `oauth-handoff` gives a harness `AUTH_REQUIRED` with `authUrl` = `/auth/connect/<sourceId>?ticket=af_ticket_…`. That page has `Continue to OAuth sign-in` and redirects to the provider.
- `oauth-callback` exchanges the code at `/auth/oauth/callback`, shows `Connected <name>`, and refreshes the source. Replayed, missing, or duplicate parameters fail closed.
- `oauth-refresh` refreshes the access token when the upstream answers 401 or the token nears expiry, then retries the call once.
- `oauth-disconnect` removes the stored tokens with `DELETE /api/sources/<id>/oauth` and returns the source to `auth_required`.
- `oauth-ui` shows `Connect OAuth`, `Reconnect`, and `Disconnect` per OAuth source, a fallback `Open OAuth sign-in page` link, and the `OAuth callback URL` notice in `Add a source`. `Disconnect` stays visible whenever the gateway holds tokens (`oauthStatus.connected`), even while the source is `degraded`.
- `oauth-reset-on-retarget` disconnects an OAuth source and drops its capabilities when its MCP URL changes, even only in path or query on the same origin, by edit or by import.
- `oauth-ticket-binding` expires a `/auth/connect` ticket once the source is edited (`Link expired`).
- `oauth-vault-isolation` rejects any source or imported bundle that references `oauth.access:*`, `oauth.refresh:*`, or `oauth.client_secret:*` with `400 INVALID_INPUT`.
- `oauth-export-secret-free` exports the OAuth configuration without tokens, states, or verifiers.

## How to get to it (user POV)

- Console: **Sources & Pool** (`#/sources`) → `Add source` → `Starter recipes` → Recipe `Remote MCP server (OAuth 2.0 / 2.1)`, or `Custom source` → Source kind `MCP server (HTTP)` → switch `Use OAuth 2.0 / 2.1`. Then use the row buttons `Connect OAuth for <name>`, `Reconnect OAuth for <name>`, and `Disconnect OAuth for <name>`.
- API: `POST /api/recipes/mcp-http-oauth/instantiate`, `POST /api/sources`, `GET /api/sources/<id>/oauth`, `POST /api/sources/<id>/oauth/start`, `DELETE /api/sources/<id>/oauth`, and `POST /api/sources/<id>/test` (returns `authHandoff.authUrl`).
- Harness: a `tools/call` into a disconnected OAuth source returns `data.code: AUTH_REQUIRED` with `data.authHandoff.authUrl`, and the error message ends with `Authenticate at <authUrl>`. The operator opens that URL in a browser.
- Browser: `/auth/connect/<sourceId>?ticket=…`, then the provider, then `/auth/oauth/callback`.

## Driving it with af-api.sh, af-mcp.sh, af-oauth-upstream.mjs, and af-browser.mjs

Preconditions:

- `$S/af-doctor.sh "$P"` reports `doctor: healthy`.
- Part A is offline. It needs nothing else and contacts no provider: `verify-oauth-offline` points at the closed loopback port `127.0.0.1:9` with explicit endpoints and a pre-registered client, so discovery and registration never run.
- Part B is the full end-to-end exchange. It needs `node $S/af-oauth-upstream.mjs`, which mocks only the external provider and remote MCP server on `127.0.0.1`. The gateway's discovery, Dynamic Client Registration, PKCE, token exchange, vault, refresh, and MCP client are real. The gateway allows plain `http` OAuth endpoints only when the MCP URL is itself loopback.
- Playwright and Chromium resolve for the UI steps.

Part A: offline checks.

- **Recipe.** Run `$S/af-api.sh "$P" POST /api/recipes/mcp-http-oauth/instantiate '{"values":{"name":"Verify OAuth MCP","url":"https://mcp.example.com/mcp","scopes":["read","write"],"extraAuthParams":["access_type=offline","prompt=consent"]}}' | jq -c '.source|{kind,health,authConfig,refreshPolicy}'`. The result is `HTTP 201`, `health:"auth_required"`, `authConfig:{"kind":"oauth2","oauth":{"scopes":["read","write"],"extraAuthParams":{"access_type":"offline","prompt":"consent"}}}`, and `refreshPolicy:{"mode":"manual"}`. Do not start authorization on this source, because discovery would contact `mcp.example.com`.
- **Custom source.** Run `$S/af-api.sh "$P" POST /api/sources '{"id":"verify-oauth-offline","name":"Verify OAuth Offline","kind":"mcp_http","config":{"kind":"mcp_http","url":"http://127.0.0.1:9/mcp"},"authConfig":{"kind":"oauth2","oauth":{"clientId":"verify-client","authorizationEndpoint":"http://127.0.0.1:9/authorize","tokenEndpoint":"http://127.0.0.1:9/token","scopes":["mcp"]}},"refreshPolicy":{"mode":"manual"}}' | jq -c '.source|{id,health}'`. The result is `{"id":"verify-oauth-offline","health":"auth_required"}`.
- **Status.** Run `$S/af-api.sh "$P" GET /api/sources/verify-oauth-offline/oauth | jq -c .oauth`. It shows `configured:true`, `connected:false`, `hasRefreshToken:false`, `redirectUri` = `<AF_URL>/auth/oauth/callback`, `clientId:"verify-client"`, and both endpoints.
- **Start.** Run `$S/af-api.sh "$P" POST /api/sources/verify-oauth-offline/oauth/start | jq -r .authorizeUrl`. The URL starts with `http://127.0.0.1:9/authorize?response_type=code&client_id=verify-client`, and has `redirect_uri`, `state=af_oauth_state_…`, `code_challenge`, `code_challenge_method=S256`, and `scope=mcp`. The transcript shows `state=af_oauth_state_[REDACTED]`. The pending state is stored only as a hash. Run `$S/af-db.sh "$P" state "select sourceId, json_extract(payload,'\$.scope'), json_extract(payload,'\$.expiresAt'), json_extract(payload,'\$.stateHash') is not null from upstream_oauth_states"`. It shows `verify-oauth-offline|mcp|<now + 10 min>|1`.
- **Harness handoff.** Run `$S/af-api.sh "$P" POST /api/sources/verify-oauth-offline/test | jq -c '{ok,health,error,authUrl:.authHandoff.authUrl}'`. It shows `ok:false`, `health:"auth_required"`, and an `authUrl` of `<AF_URL>/auth/connect/verify-oauth-offline?ticket=af_ticket_…`. The transcript masks the ticket.
- **Managed vault names are off limits.** Each of these returns `HTTP 400` with `INVALID_INPUT` `Vault names reserved for gateway-managed OAuth credentials cannot be referenced`:
  - `$S/af-api.sh "$P" POST /api/sources '{"id":"verify-steal","name":"Verify Steal","kind":"mcp_http","config":{"kind":"mcp_http","url":"http://127.0.0.1:9/mcp"},"authConfig":{"kind":"bearer_secret","secretName":"oauth.access:verify-oauth-offline"}}'`
  - `$S/af-api.sh "$P" POST /api/sources '{"id":"verify-steal2","name":"Verify Steal 2","kind":"cli_wrapper","config":{"kind":"cli_wrapper","toolName":"verify_steal","description":"x","command":"/usr/bin/echo","argsTemplate":["x"],"inputSchema":{"type":"object","properties":{}}},"authConfig":{"kind":"env_secrets","envMap":{"TOKEN":"oauth.refresh:verify-oauth-offline"}}}'`
  - `$S/af-api.sh "$P" POST /api/sources '{"id":"verify-steal3","name":"Verify Steal 3","kind":"mcp_http","config":{"kind":"mcp_http","url":"http://127.0.0.1:9/mcp"},"authConfig":{"kind":"oauth2","oauth":{"clientId":"c","clientSecretName":"oauth.client_secret:verify-oauth-offline","authorizationEndpoint":"http://127.0.0.1:9/a","tokenEndpoint":"http://127.0.0.1:9/t"}}}'`

  Second view: `$S/af-api.sh "$P" GET /api/sources | jq -c '[.sources[].id]'` lists no `verify-steal*` id.
- **Secret-free export and a poisoned import.** Run `$S/af-cli.sh "$P" export --out "$P/export.json"`. `jq -c '.sources[]|select(.id=="verify-oauth-offline")|.authConfig' "$P/export.json"` shows only the `oauth2` configuration (`clientId`, endpoints, `scopes`). `grep -cE 'af_oauth_state_|codeVerifier|stateHash|oauth\.access:' "$P/export.json"` prints `0`. Then add a thief source to the bundle: `jq '.sources += [{"id":"verify-import-steal","name":"Verify Import Steal","kind":"mcp_http","enabled":true,"config":{"kind":"mcp_http","url":"http://127.0.0.1:9/mcp"},"authConfig":{"kind":"bearer_secret","secretName":"oauth.access:verify-oauth-offline"},"refreshPolicy":{"mode":"manual"}}]' "$P/export.json" >"$P/steal-bundle.json"`. `$S/af-cli.sh "$P" import "$P/steal-bundle.json"` exits `1` with `400 INVALID_INPUT: Vault names reserved for gateway-managed OAuth credentials cannot be referenced`.
- **Callback fails closed.** Run `. "$P/session.env"`. `curl -s "$AF_URL/auth/oauth/callback"` returns `400` `Missing OAuth state parameter`. `curl -s "$AF_URL/auth/oauth/callback?state=af_oauth_state_bogus&code=x"` returns `401` `OAuth authorization session is invalid or expired`. `curl -s "$AF_URL/auth/oauth/callback?state=a&state=b"` returns `400` `Duplicate OAuth callback parameter`.
- **Console buttons and fallback link.** Run `node $S/af-browser.mjs "$P" 'goto:#/sources' 'expect:button:Connect OAuth for Verify OAuth Offline' 'click:button:Connect OAuth for Verify OAuth Offline' 'expect-text:Sign in to Verify OAuth Offline' 'expect:link:Open OAuth sign-in page' 'expect:button:Copy OAuth callback URL' 'snap:sources-oauth-prompt'`. The notice says `The link is single-use and expires in 10 minutes.`, shows the Redirect URI, and has `Done, refresh sources` and `Dismiss`. In `sources-oauth-prompt.aria.txt` the link `/url:` shows `state=af_oauth_state_[REDACTED]`.
- **Add-source callback notice.** Run `node $S/af-browser.mjs "$P" 'goto:#/sources' 'click:button:Add source' 'expect:dialog:Add a source' 'click:combobox:Recipe' 'click:option:Remote MCP server (OAuth 2.0 / 2.1)' 'expect-text:OAuth callback URL' 'expect:button:Copy OAuth callback URL' 'snap:add-source-oauth-recipe' 'click:tab:Custom source' 'click:combobox:Source kind' 'click:option:MCP server (HTTP)' 'click:switch:Use OAuth 2.0 / 2.1' 'expect-text:OAuth callback URL' 'expect:textbox:OAuth client ID' 'snap:add-source-oauth-custom'`. Both snaps show `<AF_URL>/auth/oauth/callback` under `OAuth callback URL`. The custom form shows the OAuth fields (`OAuth scopes`, `OAuth client ID`, `OAuth client secret name`, `Authorization endpoint`, `Token endpoint`, `Extra authorization parameters`) only while the switch is on.
- **Create from the console.** Run `node $S/af-browser.mjs "$P" 'goto:#/sources' 'click:button:Add source' 'click:combobox:Recipe' 'click:option:Remote MCP server (OAuth 2.0 / 2.1)' 'fill:Source name (required)=Verify OAuth UI' 'fill:MCP endpoint URL (required)=https://mcp.example.com/mcp' 'fill:OAuth scopes=read' 'click:button:Add source' 'expect:button:Connect OAuth for Verify OAuth UI' 'snap:oauth-recipe-created'`. Second view: `$S/af-api.sh "$P" GET /api/sources | jq -c '.sources[]|select(.name=="Verify OAuth UI")|{health,authConfig}'` shows `auth_required` with `{"kind":"oauth2","oauth":{"scopes":["read"]}}`.

Part B: full end-to-end exchange against the loopback boundary server.

- **Start the boundary.** Run `U=$(node $S/af-oauth-upstream.mjs "$P" --expires-in 3600); echo "$U"`. It prints `http://127.0.0.1:<port>` and writes `$P/oauth-upstream.env`. Shell variables do not persist between tool calls, so read `U` back with `. "$P/oauth-upstream.env"; U=$OAUTH_UPSTREAM_URL`.
- **Create a discovery-only source.** Run `$S/af-api.sh "$P" POST /api/sources "{\"id\":\"verify-oauth\",\"name\":\"Verify OAuth Boundary\",\"kind\":\"mcp_http\",\"config\":{\"kind\":\"mcp_http\",\"url\":\"$U/mcp\"},\"authConfig\":{\"kind\":\"oauth2\",\"oauth\":{}},\"refreshPolicy\":{\"mode\":\"manual\"}}" | jq -c '.source|{id,health}'`. The result is `{"id":"verify-oauth","health":"auth_required"}`. The empty `oauth` block makes the gateway discover the endpoints and register a client dynamically.
- **Operator connect (API).** Run `$S/af-api.sh "$P" POST /api/sources/verify-oauth/oauth/start 2>/dev/null | jq -r .authorizeUrl >"$P/.authorize-url"`. The URL has `client_id=bnd-client-…` (dynamically registered), `code_challenge_method=S256`, and `resource=<U>/mcp`. Play the provider's redirect: `curl -s -o /dev/null -w '%{redirect_url}' "$(cat "$P/.authorize-url")" >"$P/.callback"` (a `302` to `<AF_URL>/auth/oauth/callback?code=…&state=…&iss=…`). Then run `curl -s "$(cat "$P/.callback")" | grep -E '<h1>|<p'`. It prints `Connected Verify OAuth Boundary` and `1 capability discovered.`. Delete `$P/.authorize-url` and `$P/.callback` afterwards.
- **Second views.** `curl -s "$U/control/stats"` shows `registrations:1`, `authorizations:1`, `codeExchanges:1`, and `pkceFailures:0`. `$S/af-api.sh "$P" GET /api/sources/verify-oauth/oauth | jq -c .oauth` shows `connected:true`, `hasRefreshToken:true`, `scope:"mcp"`, and the discovered endpoints. `$S/af-db.sh "$P" state "select json_extract(payload,'\$.accessSecretName'), json_extract(payload,'\$.refreshSecretName'), json_extract(payload,'\$.tokenType') from upstream_oauth_tokens"` shows `oauth.access:verify-oauth|oauth.refresh:verify-oauth|Bearer`. `$S/af-api.sh "$P" GET /api/secrets | jq -c '[.secrets[].name]'` lists those two names with no values.
- **Harness call.** Run `$S/af-mcp.sh "$P" default tools/call '{"name":"oauth_boundary_echo","arguments":{"value":"first"}}' | jq -c .result.content`. The output is `[{"type":"text","text":"boundary:first (token generation 1)"}]`.
- **Automatic refresh.** Run `curl -s -X POST "$U/control/revoke"` (`{"revoked":true}`), then `$S/af-mcp.sh "$P" default tools/call '{"name":"oauth_boundary_echo","arguments":{"value":"after revoke"}}' | jq -c .result.content`. The call still succeeds with `boundary:after revoke (token generation 2)`. `$U/control/stats` now shows `mcpRejected:1` and `refreshes:1`, which means the gateway got a 401, rotated the refresh token, and retried. For expiry-driven refresh, start the boundary with `--expires-in 61` instead. The gateway refreshes any token that expires within 60 s before using it.
- **Disconnect.** Run `$S/af-api.sh "$P" DELETE /api/sources/verify-oauth/oauth` (`{"ok":true}`). `GET /api/sources/verify-oauth` shows `health:"auth_required"` and `lastError:"Upstream OAuth disconnected"`. `GET /api/secrets` no longer lists `oauth.*:verify-oauth`.
- **Harness handoff to the connect page.** Run `$S/af-mcp.sh "$P" default tools/call '{"name":"oauth_boundary_echo","arguments":{"value":"after disconnect"}}' | jq -c '.error.data|{code,authUrl:.authHandoff.authUrl}'`. The result is `code:"AUTH_REQUIRED"` with `authUrl` = `<AF_URL>/auth/connect/verify-oauth?ticket=af_ticket_…`. Get a ticket the same way through the API: `$S/af-api.sh "$P" POST /api/sources/verify-oauth/test 2>/dev/null | jq -r .authHandoff.authUrl >"$P/.connect-url"`. Then run `curl -s "$(cat "$P/.connect-url")" >"$P/.connect.html"` and `grep -E '<h1>|<dt>|<button' "$P/.connect.html"`. The page shows `Connect Verify OAuth Boundary`, `MCP endpoint`, `Redirect URI`, and the button `Continue to OAuth sign-in`.
- **Submit the connect page.** Run `. "$P/session.env"; TICKET=$(grep -o 'name="ticket" value="[^"]*"' "$P/.connect.html" | sed 's/.*value="//; s/"$//')`, then `curl -s -o /dev/null -w '%{redirect_url}' --data-urlencode "ticket=$TICKET" "$AF_URL/auth/connect/verify-oauth" >"$P/.provider"`. The answer is a `303` to `<U>/authorize?…`. Then run `curl -s -o /dev/null -w '%{redirect_url}' "$(cat "$P/.provider")" >"$P/.callback"` and `curl -s "$(cat "$P/.callback")" | grep '<h1>'` (`Connected Verify OAuth Boundary`). Replaying the same callback URL returns `401` `OAuth authorization session is invalid or expired`. Re-posting the same ticket returns `403` `Link expired`. Delete `$P/.connect-url`, `$P/.connect.html`, `$P/.provider`, and `$P/.callback`, because they hold raw single-use values.
- **Same-origin URL change resets the connection.** While `verify-oauth` is connected, run `$S/af-api.sh "$P" PATCH /api/sources/verify-oauth "{\"config\":{\"kind\":\"mcp_http\",\"url\":\"$U/mcp?tenant=b\"}}" | jq -c '.source|{health,lastError}'`. The result is `{"health":"auth_required","lastError":"Upstream credentials are required or were rejected"}`. `GET /api/sources/verify-oauth/oauth` shows `connected:false` and `hasRefreshToken:false`. `GET /api/secrets` no longer lists `oauth.*:verify-oauth`, and `GET '/api/capabilities?profileId=default'` no longer lists `oauth_boundary_echo`. Connect again (the API steps above) before you continue. The boundary ignores the query string, so `1 capability discovered.` comes back.
- **Disconnect stays visible while degraded.** With the source connected, pause the boundary with `. "$P/oauth-upstream.env"; kill -STOP $OAUTH_UPSTREAM_PID`. Then set a short timeout without changing the URL: `$S/af-api.sh "$P" PATCH /api/sources/verify-oauth "{\"config\":{\"kind\":\"mcp_http\",\"url\":\"$U/mcp?tenant=b\",\"timeoutMs\":1500}}"`. The result shows `health:"degraded"`, and `GET /api/sources/verify-oauth/oauth` still shows `connected:true`. Run `node $S/af-browser.mjs "$P" 'goto:#/sources' 'expect:button:Connect OAuth for Verify OAuth Boundary' 'expect:button:Disconnect OAuth for Verify OAuth Boundary' 'snap:oauth-degraded-disconnect-visible'`. The row reads `degraded` / `Upstream operation timed out` and offers both buttons. Resume with `kill -CONT $OAUTH_UPSTREAM_PID` before the next step.
- **Full console journey.** Run `node $S/af-browser.mjs "$P" 'goto:#/sources' 'click:button:Disconnect OAuth for Verify OAuth Boundary' 'expect:alertdialog:Disconnect Verify OAuth Boundary?' 'click:button:Disconnect' 'expect-text:Disconnected Verify OAuth Boundary' 'expect:button:Connect OAuth for Verify OAuth Boundary' 'snap:oauth-disconnected' 'click:button:Connect OAuth for Verify OAuth Boundary' 'expect-text:Sign in to Verify OAuth Boundary' 'click:button:Done, refresh sources' 'expect:button:Reconnect OAuth for Verify OAuth Boundary' 'snap:oauth-reconnected-ui'`. The console's popup goes through the boundary's auto-consenting `/authorize` and back to the gateway callback in headless Chromium. `$U/control/stats` gains one registration, one authorization, and one code exchange.
- **Proof.** Keep the `*oauth*` transcripts, `oauth-upstream.log` (events and counters only, with no token values), the `browser/*oauth*` snaps, and `export.json`. After `af-cleanup.sh`, run `grep -rlE 'bnd_(access|refresh|code)_|af_(oauth_state|ticket|code|refresh)_[A-Za-z0-9]{6}' "$P"`. It must print nothing, which proves no upstream token, code, state, or ticket reached the evidence.

## Gotchas

- Starting authorization on a non-loopback URL with no explicit endpoints runs real discovery against that host. Keep offline runs on `127.0.0.1` with explicit `authorizationEndpoint`, `tokenEndpoint`, and `clientId`.
- Plain `http` OAuth URLs are accepted only when they and the MCP URL are loopback. Anything else returns `400` `Upstream OAuth URLs must use HTTPS or permitted HTTP loopback`.
- Recipe-created source ids are UUIDs. Read the id from the response, or pick the row by `name`.
- Helper transcripts mask states, tickets, and `code=`, so take raw values from stdout (`2>/dev/null | jq -r …`) into a file under `$P`, and delete that file after use. Never paste them into the report.
- Each `oauth/start` and each `POST /auth/connect` creates a new pending state (10 min), and each ticket is single-use. A ticket used by a mistyped `curl` is spent: get a fresh one with `POST /api/sources/<id>/test`.
- `curl` refuses to mix `--form-string` and `--data-urlencode`. The connect page is a urlencoded form, so use `--data-urlencode` alone.
- The row button names are `Connect OAuth for <name>` while the source is not healthy, and `Reconnect OAuth for <name>` plus `Disconnect OAuth for <name>` once it is healthy. The confirm is an `alertdialog`, not a `dialog`.
- `Done, refresh sources` can race the popup on a slow machine. If `Reconnect OAuth for …` does not appear, rerun with `goto:#/sources` before asserting.
- Every reconnect after a disconnect registers a new dynamic client, because disconnect clears the registration. Assert counter deltas, not absolute totals.
- Changing the MCP URL (any part, including only its path or query), the endpoints, client id, client secret name, auth method, or resource on an OAuth source disconnects it and drops its discovered capabilities. An import that changes them does the same. A change to `timeoutMs` or the name keeps the connection.
- Any edit to a source, including a rename or `timeoutMs`, spends the `/auth/connect` tickets handed out for it. They answer `403` `Link expired`. See [security-lifecycle.md](./security-lifecycle.md).
- A paused (`kill -STOP`) boundary still holds its port and PID. Resume it with `kill -CONT` before `af-cleanup.sh`, or the cleanup waits on a stopped process. SIGTERM is delivered only after the process continues.
- Only one `af-oauth-upstream.mjs` per proof dir. It exits by itself after `--ttl` (900 s), and `af-cleanup.sh` stops it earlier.
