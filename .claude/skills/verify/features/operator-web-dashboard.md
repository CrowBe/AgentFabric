# Operator web dashboard and REST API

The operator signs in to the console at `/` with the operator token. The console then manages sources and the capability pool, agent skills (including GitHub skill repos), profiles, client tokens, OAuth clients, and the write-only secret vault. Every console action goes through the operator REST API `/api/*`, which fails closed without the operator token.

## Sub-features

- `ui-token-gate` blocks the console behind the "Operator sign-in" dialog and rejects a wrong token.
- `ui-overview` shows gateway status, source health, and harness connect snippets per profile. Switching the `Profile` select drops a token minted for the previous profile and shows only the new profile's snippets.
- `ui-sources-pool` lists sources with health and the capability pool with exposure, permission, and status. The `Exposure as profile` filter starts at `default`.
- `ui-auth-required-stays-signed-in` keeps the operator signed in when an action fails with an upstream `401 AUTH_REQUIRED`. Only an operator `401 UNAUTHORIZED` reopens the token gate.
- `ui-recipes` lists the starter recipes in `Add a source`, including `CLI wrapper` (`cli-wrapper-readonly`). The `Composite tool` custom form pre-fills `Steps (JSON array)` with `"capability": "exposed_tool_name"`.
- `ui-folders-read-only` shows each shared folder with Access `read-only`. Its `Edit <share>` dialog has no read-write control and says `Shared folders are always read-only.`
- `ui-wording` shows the rule precedence and direct-tool budget text in Profiles and the merge and replace text in Portability.
- `ui-skills` shows **Skills & Folders**: the `Import from GitHub URL` bar, one card per skill repo with a searchable skill list, and an on-demand `SKILL.md` preview with attached files.
- `ui-mobile` switches to a single column with a horizontal, scrollable `Gateway sections` tab bar at narrow widths (390 px), so every view stays reachable.
- `ui-profiles` lists profiles and creates one through the `New profile` dialog.
- `ui-tokens` mints a scoped bearer token that is shown once.
- `ui-secrets` stores a secret whose value is never readable again.
- `api-fail-closed` returns 401 for `/api/*` without the operator token and rejects unknown fields with 400 `INVALID_INPUT`.

## How to get to it (user POV)

- Open the `Web UI` URL from the startup banner and paste the operator token from `<home>/operator-token`.
- Use the vertical tab list `Gateway sections`: `Overview & Connect`, `Sources & Pool`, `Skills & Folders`, `Profiles & Discovery`, `Safety & Approvals`, `Events`, `Auth & Secrets`, `Telemetry & Portability`. Hash routes are `#/overview`, `#/sources`, `#/skills`, `#/profiles`, `#/safety`, `#/events`, `#/auth`, `#/telemetry`.
- Call `/api/*` with `Authorization: Bearer <operator token>` (or `x-operator-token`).

## Driving it with af-browser.mjs

Preconditions:

- `$S/af-doctor.sh "$P"` reports `doctor: healthy`.
- The **Echo tool** fixture from `README.md` is seeded.
- Playwright and Chromium resolve (see `../SKILL.md` Drive).

- **Wrong token.** Submit a bad token. Run `node $S/af-browser.mjs "$P" --no-signin 'expect:dialog:Operator sign-in' 'fill:Operator token=afop_wrong' 'click:button:Sign in' 'expect-text:That operator token was not accepted.' 'snap:gate-rejected'`. The dialog stays open with the error notice.
- **Sign in and overview.** Sign in with the real token. Run `node $S/af-browser.mjs "$P" 'expect:heading:Overview' 'expect:region:Connect a harness' 'snap:overview'`. The tablist `Gateway sections` appears, the banner shows `local mode`, and the page title is `Overview & Connect · AgentFabric`.
- **Sources and pool.** Open the tab. Run `node $S/af-browser.mjs "$P" 'click:tab:Sources & Pool' 'expect:heading:Sources & Pool' 'expect-text:Verify Echo' 'snap:sources'`. The `Configured sources` table shows `Verify Echo` as `CLI wrapper` and `healthy`. `Capability pool` shows `verify_echo` as `direct` and `allow`.
- **Skills view and in-gateway preview.** Seed the **Release skill** fixture, then run `node $S/af-browser.mjs "$P" 'goto:#/skills' 'expect:heading:Skills & Shared Folders' 'expect:region:Agent skills' 'expect:textbox:Import from GitHub URL' 'expect:article:Skill Release checklist' 'click-text:Preview content' 'expect:region:Release checklist content' 'snap:skills'`. The preview region shows `# Release checklist`.
- **GitHub import bar, rejected URL (offline).** Run `node $S/af-browser.mjs "$P" 'goto:#/skills' 'fill:Import from GitHub URL=https://gitlab.com/example/skills' 'click:button:Import' 'expect-text:GitHub import failed' 'expect-text:Unsupported host' 'snap:skills-import-rejected'`. No card is added. `$S/af-api.sh "$P" GET /api/sources | jq -c '[.sources[]|select(.kind=="skill_repo")]'` is unchanged.
- **GitHub import and SKILL.md preview (needs GitHub HTTPS).** Run `node $S/af-browser.mjs "$P" 'goto:#/skills' 'fill:Import from GitHub URL=https://github.com/anthropics/skills/tree/main/skills/docx' 'click:button:Import' 'expect-text:Imported skills' 'expect:article:Skill repo docx' 'click-text:Browse skills (1)' 'click:button:Preview docx SKILL.md' 'expect:region:docx SKILL.md' 'expect:button:Hide docx SKILL.md' 'snap:skills-repo-preview'`. The card shows `GitHub`, `1 skill`, `healthy`, the repo URL with `ref main · path skills/docx`, and the preview region starts with the skill's frontmatter. Second view: `$S/af-cli.sh "$P" skills list` lists `docx` from source `docx`.
- **Overview snippets follow the selected profile.** Create a second profile (`$S/af-api.sh "$P" POST /api/profiles '{"name":"verify-alt"}'`). Run `node $S/af-browser.mjs "$P" 'goto:#/overview' 'expect:region:Connect a harness' 'click:combobox:Profile' 'click:option:default' 'click:button:Mint token' 'expect-text:Token minted. It is shown only once.' 'click:combobox:Profile' 'click:option:verify-alt' 'expect-text:/mcp/verify-alt' 'snap:overview-profile-switched'`. In `overview-profile-switched.aria.txt`, `combobox "Profile"` reads `verify-alt`, the `MCP URL` code is `<AF_URL>/mcp/verify-alt`, `grep -c 'af_tok_\|shown only once'` prints `0`, and only the `Token minted` toast remains.
- **Pool filter defaults to `default`.** Run `node $S/af-browser.mjs "$P" 'goto:#/sources' 'expect:combobox:Exposure as profile' 'snap:sources-profile-default'`. The ARIA line is `combobox "Exposure as profile": default`, even when newer profiles exist.
- **Upstream `AUTH_REQUIRED` keeps the session.** Seed `verify-oauth-offline` from [upstream-oauth.md](./upstream-oauth.md) Part A (`auth_required`). `$S/af-api.sh "$P" POST /api/sources/verify-oauth-offline/refresh` returns `HTTP 401` `AUTH_REQUIRED` with an `authHandoff`. Run `node $S/af-browser.mjs "$P" 'goto:#/sources' 'click:button:Refresh Verify OAuth Offline' 'expect-text:Upstream credentials are required' 'expect:tablist:Gateway sections' 'snap:sources-auth-required-stays-signed-in'`. The error shows inline, the `Operator sign-in` dialog does not open, and the tab list stays.
- **Recipes and the composite example.** Run `node $S/af-browser.mjs "$P" 'goto:#/sources' 'click:button:Add source' 'expect:dialog:Add a source' 'click:combobox:Recipe' 'expect:option:CLI wrapper' 'click:option:CLI wrapper' 'snap:recipe-cli-wrapper' 'click:tab:Custom source' 'click:combobox:Source kind' 'click:option:Composite tool' 'expect-text:"capability": "exposed_tool_name"' 'snap:composite-steps-example'`. - **Mobile layout.** Run `node $S/af-browser.mjs "$P" --viewport 390x844 'expect:tablist:Gateway sections' 'click:tab:Sources & Pool' 'expect:heading:Sources & Pool' 'expect:button:Add source' 'snap:mobile-sources' 'click:tab:Skills & Folders' 'expect:heading:Skills & Shared Folders' 'expect:button:Import' 'snap:mobile-skills'`. Both PNGs are exactly 390 px wide (`file "$P"/browser/mobile-*.png`), so nothing overflows sideways. For the newer views, also run `node $S/af-browser.mjs "$P" --viewport 390x844 'click:tab:Safety & Approvals' 'expect:heading:Safety & Approvals' 'snap:mobile-safety' 'click:tab:Events' 'expect:table:Event occurrences' 'snap:mobile-events'`, and check that these PNGs are 390 px wide too. The tab bar runs across the top, the Sources table renders as stacked per-source cards with the same row buttons (for example `Reconnect OAuth for <name>`), and the GitHub `Import` button spans the full width under the URL field.
- **Create a profile.** Run `node $S/af-browser.mjs "$P" 'goto:#/profiles' 'click:button:New profile' 'fill:Name (required)=verify-ui' 'click:button:Create profile' 'expect-text:verify-ui' 'snap:profiles'`. - **Mint a token.** Run `node $S/af-browser.mjs "$P" 'goto:#/auth' 'expect:heading:Auth & Secrets' 'fill:Label (required)=verify ui token' 'click:button:Mint token' 'expect-text:Copy this token now. - **Store a secret.** Run `node $S/af-browser.mjs "$P" 'goto:#/auth' 'fill:Secret name (required)=verify_api_key' 'fill:Value (required)=sk-verify-SECRET-123' 'click:button:Store secret' 'expect-text:verify_api_key' 'snap:secret-stored'`. Second view: run `$S/af-api.sh "$P" GET /api/secrets`, which lists `verify_api_key` with no `value` field. `grep -r sk-verify-SECRET-123 "$P"` finds nothing.
- **API fails closed.** Run `AF_NOAUTH=1 $S/af-api.sh "$P" GET /api/status` (`HTTP 401`, `UNAUTHORIZED`). Then run `$S/af-api.sh "$P" POST /api/profiles '{"name":"x","bogus":true}'` (`HTTP 400`, `INVALID_INPUT` naming the unrecognized key).
- **Proof.** Keep `$P/browser/*.png`, `*.aria.txt`, `console.txt`, and the `/api` transcripts. `console.txt` should hold only the expected `401` from the wrong-token step.

## Gotchas

- The operator token field is a password input, so it has no `textbox` role. Use `fill:Operator token=…` (label), not a role.
- The token lives in `sessionStorage`. Each `af-browser.mjs` run is a fresh tab and signs in again. Pass `--no-signin` only to test the gate.
- Tab names and h1 headings differ for two views: tab `Overview & Connect` has h1 `Overview`, and tab `Skills & Folders` has h1 `Skills & Shared Folders`.
- The `Profile` select in `Scoped bearer tokens` defaults to the first listed profile, which is the newest one, not `default`. The helper has no select step, so assert the minted token's `profileId` through `GET /api/tokens` instead of assuming `default`.
- Secret values are write-only. Never assert a value round-trip. Assert the name and the absence of the value everywhere, including exports.
- Minted token values appear once in the UI and in `POST /api/tokens`. Transcripts mask `af_tok_…`, but screenshots do not. Treat `token-minted.png` as sensitive, even though the instance is disposable.
- Lists refresh on intervals (approvals SSE, 20–30 s polls elsewhere). After an API-side mutation, reload with `goto:` before asserting in the UI.
- `<details>` summaries (`Preview content`, `Browse skills (N)`, `Optional filters & private repo auth`, `What agents see`) have no ARIA role or name. Open them with `click-text:<exact summary text>`.
- Each skill inside a repo card has a toggle named `Preview <slug> SKILL.md` (switching to `Hide <slug> SKILL.md` when open), and its opened region is named `<slug> SKILL.md`.
- The per-repo `Filter <name> skills` box appears only when a repo card holds more than 5 skills.
- A repo imported from `/tree/<ref>/<subpath>` with no name gets the subpath's last segment as its name (`docx`), and its card is `Skill repo docx`.
- `--viewport` takes `<W>x<H>`. The layout switches to mobile at 54rem (864 px) wide.
- The read-only rule is strict only in **Skills & Folders** (`Edit <share>`). The `Shared workspace folder` recipe behind `Share a folder`, and the custom `Shared folder` form, still render a `Read-only` switch (default on), and `POST /api/sources` accepts `readOnly:false`. The gateway exposes no write path for folders either way. Assert the Edit dialog and the `read-only` pill, not the recipe form.
- The `Profile` and `Exposure as profile` selects are comboboxes. Drive them with `click:combobox:<label>` then `click:option:<profile name>`.
- `Edit <profile>` buttons are named after the profile name (`Edit default`). The budget help and the rule-precedence text appear only inside the open editor.
